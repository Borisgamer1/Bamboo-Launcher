# Bamboo Launcher 0.2.8

CurseForge läuft wieder ohne Einrichtung: Der Launcher bringt seinen Key mit,
und zwar in jedem Build. Niemand trägt mehr einen eigenen Key ein – Suche,
Projektseiten, Modpack-Importe und Inhalts-Updates nutzen alle denselben Key.
Ein abgelaufener Key aus einer alten Installation kann die Mod-Suche nicht
mehr blockieren.

## Behoben

- **CurseForge ohne eigenen Key:** Der Key wird beim Bauen fest in den Launcher
  eingebettet (`resources/curseforge-key.txt`) und gilt für alle Nutzer.
- **Alte Keys greifen nicht mehr:** Keys aus früheren Fassungen, aus
  `ui-settings.json`, `settings.json` und der Electron-Einstellungsdatei werden
  ignoriert. Ein dort abgelaufener Key meldete bisher „Key ungültig“, obwohl
  der Launcher längst einen gültigen Key mitbringt.
- **Ressourcenpakete aus Modpacks:** Ein `.zip` im CurseForge-Manifest ist ein
  Ressourcen- oder Shaderpaket. Es landet jetzt in `resourcepacks/` bzw.
  `shaderpacks/` statt als „keine .jar“ abgelehnt zu werden.
- **Fehlerhafte Dateien überspringen den Import:** Eine Datei, die sich nicht
  laden lässt, bricht den Pack nicht mehr ab. Am Ende stehen die übersprungenen
  Dateien samt Grund im Bericht, der Rest der Instanz ist fertig.
- **Importierte Instanzen stimmen:** Der Export legt Name, Minecraft-Version,
  Loader, Bild, Beschreibung und RAM unter `instance` ab. Der Import las nur
  die oberste Ebene und machte aus jedem Pack „Profil“ mit Minecraft 1.21.
  Jetzt kommen alle Angaben an, und der Loader aus dem Manifest wird beim
  Import gleich mitinstalliert.
- **Versionswechsel erkennt Store-Metadaten:** Bei importierten Instanzen
  fehlten Projekt-ID und Quelle; der Wechsel fand keine Store-Version und
  hätte die Dateien entfernt. Jetzt werden sie über SHA-1/Fingerprint
  identifiziert und in der Bestandsdatei vermerkt. Unbekanntes bleibt stehen.
- **Startfehler sind sichtbar:** Schlägt der Start fehl, erscheint eine
  Meldung statt eines kurzen Ladeblitzes. Beendet sich Minecraft unerwartet,
  nennt ein Hinweis den Exit-Code und verweist auf die Crash-Analyse.
- **CurseForge-Mods passen zum Loader der Instanz:** Die CurseForge-API nennt
  den Loader einer Datei nur in ihrer Versionsliste, nicht als eigenes Feld.
  Bisher galt jede Datei als loaderlos – aus einer CurseForge-Suche konnte so
  eine NeoForge-Datei in einer Fabric-Instanz landen. Jetzt zählt der Loader
  aus der Versionsliste, und nur passende Dateien werden angeboten.
- **Mod-Version wechseln funktioniert wieder:** Beim Wechsel einer
  CurseForge-Mod auf eine andere Version fehlten Projekt-ID und Quelle in der
  Anfrage; der Wechsel brach mit „CurseForge-Projekt-ID fehlt“ ab. Beides wird
  jetzt mitgeschickt, und die Mod bleibt ihrem Projekt zugeordnet.
- **Minecraft installiert sich beim Anlegen der Instanz selbst:** Fehlt die
  Basisversion (z. B. `26.3`), lädt der Launcher sie samt Java, Libraries und
  Assets herunter, bevor die Instanz fertig ist. Bisher endete das Anlegen mit
  „Basisversion nicht installiert“. Dasselbe gilt beim Versionswechsel und
  beim Start einer Instanz.
